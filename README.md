## SLO сонголт тайлбар

30 VU-гийн baseline p95 (302.06ms)-ийг SLO-гийн үндэслэл болгож сонгосон. 5 VU дээрх
sample size хэт бага (102 хүсэлт) байсан тул нэг удаагийн удаан хариу (max=1.64s)
статистикийг их хазайлгасан — иймд түүнийг baseline болгож ашиглах нь тохиромжгүй
гэж үзсэн. 30 VU дээр 1302 хүсэлт цугласан тул илүү тогтвортой хэмжилт өгсөн.

SLO = baseline p95 (302.06ms) × 1.5 ≈ **453ms**

- `results/run-30vu-slo.txt`: `p(95)<453ms` threshold-той 30 VU дээр ажиллуулахад
  **PASS** гарсан (бодит p95=262.87ms).
- `results/run-100vu-slo-fail.txt`: FAIL кэйс харуулах зорилгоор санаатайгаар хатуу
  `p(95)<200ms` threshold тогтоож 100 VU дээр ажиллуулахад **FAIL** гарсан
  (бодит p95=256.6ms). Энэ нь бодит SLO биш — зөвхөн PASS/FAIL хоёуланг үзүүлэх
  зорилготой туршилт.

## Дүгнэлт

1. Load тестийг зөвшөөрөлтэй дадлагын сайт test.k6.io дээр гүйцэтгэсэн бөгөөд
   бусад бодит вебсайт руу тест хийгээгүй.
2. VU тоо 5-с 100 болтол нэмэгдэхэд throughput шугаман бус боловч тогтвортой
   өссөн (6.58 → 41.49 → 147.60 req/s).
3. Бүх түвшинд error rate 0.00% байсан нь target сервер өгөгдсөн ачааллыг
   хүндрэлгүй даасныг харуулна.
4. 5 VU дээрх p95 (725.58ms) бусад түвшнээс хамаагүй өндөр гарсан нь цөөн
   sample size дээр нэг удаагийн удаашрал статистикт их нөлөөлдгийг харуулав.
5. VU нэмэгдэх тусам p95 latency бага зэрэг буурсан нь сервер талын connection
   reuse болон дулаарсан кэштэй холбоотой байж болзошгүй.
6. Threshold-оо зөв тогтоохын тулд зааврын жишээ тоог шууд хуулбарлахгүй,
   өөрийн бодитоор хэмжсэн baseline дээр үндэслэх нь чухал болохыг ойлгов.
7. options дотор stages ашиглаагүй тул 5/30/100 VU-г тус тусад нь commandline
   flag-аар ялгаатай ажиллуулж, тус бүрдээ тусдаа summary авч чадсан.
8. `k6 run ... | tee results/...` команд ашигласнаар терминал дээрх гаралт
   болон файл руу хадгалагдсан гаралт хоёул ижил агуулгатай байлгав.
9. FAIL кэйсийг зориудаар хатуу threshold тогтоож гаргасан — энэ нь бодит SLO
   (453ms) биш, зөвхөн PASS/FAIL хоёуланг харьцуулж үзүүлэх зорилготой.
10. Цаашид илүү нарийвчилсан дүн шинжилгээ хийхийн тулд WebSocket, POST хүсэлт
    зэрэг илүү олон төрлийн endpoint дээр туршиж болно.
